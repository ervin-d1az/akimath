## The critical one shipped, and it is in our own evidence screenshot

**Every prompt's `=` was clipped in half.** `GlyphMeasure` took `(text, size)` and no face, so the
adapter could only measure in one family — and it measured in Darumadrop while D7 paints `=` in Plus
Jakarta 800. Measured from the bundled TTFs, `=` advances **334/1000 em** in Darumadrop against
**606/1000** in Plus Jakarta. At 76 px the glyph was allotted 25.4 pt and painted 40.1: **43 % of the
mark fell outside its box**, and `Stack`'s default `Clip.hardEdge` cut it off silently. Every item in
the pack ends in `=`.

Two things about this are worth keeping.

**It was photographed and shipped.** `spike-b/tier2-compositor.png` and
`f2-core-loop/evidence/round-playable.png` both show it — two squat blocks with a hard vertical cut,
aspect ratio about 1.7:1 where the real glyph is 5:1. Tier 2 was run three times over this screen and
the defect was looked at each time and read as the typeface's design. Compare
`spike-b/tier2-equals-fixed.png`.

**No test could have caught it.** The suite loads no fonts, so every family resolves to the same
fixed-width test font and the two measure identically. The one containment assertion checked
`outer.contains(child.topLeft)` — the *left* corner, which an overflow on the right can never
violate — and its subject was a fraction, which has no `textHeavy` leaf at all.

The fix threads `MathFace` through `GlyphMeasure`, and `_measure` and `_styleFor` now share one
`_styleForFace` so the measured and painted styles cannot disagree again. The stand-in measure in
`math_node_test.dart` now returns the **real** two ratios, so a face-blind implementation fails.

## The canonicaliser disagreed with the frozen contract

Found by differential fuzzing the real `packages/contract/src/canon.ts` against the real Dart over
22,440 inputs — **41 outcome divergences**, all one family: the integer branch suppressed the sign on
`-0` and the fraction branch re-applied it, so `-0/5` canonicalised to `-0/5` in Dart and `0/5` in
TypeScript. Worse, Dart **accepted** `-0/5` as storage-canonical where the contract rejects it.

Reachable through content, not just across the wire: a pack authored with `"answer": "-0/5"` passed
`Pack._item`'s guard, loaded clean, and would tell a child typing `0/5` they were wrong — the exact
harm that guard's own comment describes.

**The golden fixture did not catch it: its 19 vectors contain no `-0/n` case.** A shared oracle is
the right idea and it is only as wide as its vectors.

Also closed: **4,916 tag-only divergences**. Dart hard-coded six digit blocks, four combining ranges
and five invisible code points where TypeScript uses `\p{Nd}`, `\p{M}` and a wider set, and the two
checked in different orders. No verdict moved, but the tags are a shared contract a caller may switch
on.

**Re-verified the same way it was found:** 5,219 inputs × 2 modes = **10,438 comparisons, 0
divergences** of either kind.

## The slot truncated what it graded

140 px holding `BrandText.numeral(40)`, where a Darumadrop `0` advances ~27 px — five or six digits,
against `AnswerDraft.maxLength` of twelve. `maxLength`'s own comment claimed it was "short enough
that a child holding a key cannot overflow the slot", which was false by about 2.3×.

The harm was not only cosmetic: the answer *shown* and the answer *graded* differed, and backspacing
a hidden character looked like a keypress that did nothing. Now a `FittedBox` scales to fit, and two
tests assert the full draft is displayed and that backspace always changes the screen.

## Two keys could only ever produce a wrong verdict

`KeypadLayout.item` ships `,` and `²` because the design draws them. The frozen answer shape admits
**neither**, so one tap on either produced a draft `grade` could only score wrong — and `canSubmit`
returned true for a draft of nothing but `,`. Two keys of sixteen that punished a child for the app's
own gap.

`AnswerDraft` now accepts only characters a canonical answer can contain, so a mis-tap costs nothing.

**That is the safe half. The other half is a decision nobody has taken** — either the contract grows
a decimal answer shape, or those two keys come off the item pad. Recorded here rather than settled,
because it is a design and contract question, not a code one.

## Conventions

Two PURE-1 blockers, both closed by moving code:

- **`_nodeFor` out of `RoundScreen`** into `features/round/policy/prompt_layout.dart`. It is the
  mapping from a prompt to a node tree — "what a drawing is" — sitting in a widget, and its
  `FractionToken` arm had **no assertion anywhere**: the round tests build items from text and
  operators, and the gates that pump the registry's fraction item check blur, overflow and text
  decoration rather than tree shape. Five tests now cover it, including that a swapped numerator
  fails.
- **`CageOutline` out of `dashed_border_painter.dart`** into `design/painting/spec/`. Const design
  geometry in a file importing `package:flutter/widgets.dart`, breaking the boundary that file's own
  doc comment states. **The move then failed the pure gate itself** — importing the tokens *barrel*
  smuggles `package:flutter/painting.dart` in through `brand_typography`, exactly the case
  `CLAUDE.md` warns about. Fixed by importing `brand_shape.dart` directly.

Should-fix, all closed: BRD-2c reasons or tokens for four unexplained numbers on the round screen and
`VerdictRing`'s default size; a missing Tier 1 entry for the asset reader; an evidence path that
resolved to nothing; two delta-spec pointers to a deleted test and to a field no type has.

Three observations acted on: `IconFace.glyph` is now a `BrandGlyph` rather than a `String` — its
stated rationale ("this module holds no widget import") was disproved by a sibling pure module in the
same diff; `MathTone.muted` is **removed**, because it had no producer while a test pinned the enum,
so the assertion read as coverage of an unreachable adapter arm; and two stale doc lines corrected.
