## The two criticals were both invisible to a green suite

### A daylight-saving transition destroyed an earned streak

`streakLength` walked backwards with `subtract(const Duration(days: 1))`. A `Duration` is absolute
elapsed time; a local calendar day is 23, 24 or 25 hours long. The days are a set of local midnights,
so on the day after a transition the lookup simply missed.

Two mechanisms, one fix. The **grace path** — the branch that exists so a child is not punished for
opening the app before playing — returned **0**, the whole streak. The **counting loop** skipped the
transition day, so every run spanning it was permanently one short.

Reproduced rather than argued, in `America/Tijuana`, with a 30-day run on the morning of 9 March 2026:

```
home  (not played today): 0   want 30
verdict (played today):   29  want 30
```

**Same child, same morning, two screens, and neither number right.** Tijuana and Ciudad Juárez are
Mexican DST zones — this is the audience, not a travelling device. It also reached Santiago, Havana,
Madrid and every US and European zone.

Fixed with component arithmetic — `DateTime(y, m, d - 1)` normalises day zero into the previous month
and always lands on that calendar day's local midnight, whatever the offset does. Verified across six
zones, both paths.

**The part worth keeping is why the suite could not see it.** `America/Mexico_City` abolished DST in
2022 and CI runs UTC, so both are clean columns. With the fix reverted, `flutter test` is **green**
and only the DST run fails, with `0`, `29` and `4`. So CI now runs the streak tests a second time
under `TZ=America/Tijuana`, and the test file says plainly that it passes vacuously without it.

### On iOS a child who started a series could never get back

Four exits, all closed. `fullscreenDialog` routes get no `_CupertinoBackGestureDetector`, so no
edge-swipe. iOS has no system back button. The session had no app bar and neither screen carried a
close control. And the round never ends — `_next` is a modulo cycle, so every button led to another
item.

`main.dart` stated the intent exactly: *"a series has no navigation affordance and the only way out is
its own control."* **The affordance was removed and the control was never added.** Android hid it,
because hardware back pops the route.

The design had specified it all along — `req-item-shell` renders the item as *close · progress dots ·
stimulus slot · answer card · keypad*. The close control now exists on both the item and the verdict,
defaulting to `Navigator.maybePop` so a pushed round always has an exit even if a caller forgets one.

**The test that should have caught this called `Navigator.pop` directly.** It proved the *route* was
poppable; it never proved a *player* could pop it. It now taps what a player can see, and a third test
asserts the general rule: whatever a session shows, it shows a way out.

## The three blocking findings were one shape

All three were assertions that could not distinguish the code from its inverse.

- **A tautology.** `text.width * (slot.width / text.width) <= slot.width + 0.5` reduces to
  `slot.width <= slot.width + 0.5`. Mine, written to hold down a painting defect that had shipped,
  holding nothing. Now checks both corners of the rendered rect, and falsified: removing the
  scale-to-fit gives `Expected: true / Actual: <false>`.
- **Unreached catch arms.** Both of `PrefsDayLogStore`'s, because the only backend in the tests never
  fails — and the write arm was the half the original incident was on. A deliberately failing backend
  now covers both.
- **A widget with no test file.** `InlineBanner` shipped four decisions unasserted, while the policy
  test's `hasLength(2)` over `BannerPlacement.values` read as coverage of arms nothing rendered.

That is the fourth time this shape has bitten — `MathTone.muted` was the third. So it is now a rule:

> **PROC-11** MUST: an assertion that holds for any input is not a test. […] The remedy is the same in
> every case: state the mutation the test would catch, then make it.

## Two rule conflicts, resolved rather than noted

**DEP-1 said "state in the PR"; `CLAUDE.md` blessed the allowlist.** `CLAUDE.md` wins, and it is also
right: a PR body is not greppable, not versioned beside the entry, and fails no build. DEP-1 now names
`dependency_allowlist_test.dart` as the audit's home, with `shared_preferences` as the worked example.

**LANG-1 did not authorise quoting Spanish in an English comment**, which three files do and which
survived a full round unflagged. It now does, with the condition that the rationale around the
quotation is English — paraphrasing a source loses the ability to check it against the source.

## Also closed

`RoundRoute` deleted: dead in production since the home landed, and duplicating `HomeRoute`'s pack
load, expiry refusal and error message. Two adapters to keep in agreement, one unreachable.

Five stat radii and the pill's height moved into `BrandShape` under their own names, because the
tokens file's own convention is to name by surface so a screen asks for a tile rather than borrowing
a button's number. Four remaining bare sizes got the one-line reason BRD-2c asks for.

`f2-day-log` shipped persistence with **no requirement covering it** — the one behaviour with
two-launch device evidence, and `/opsx:archive` would have folded a permanently silent capability into
the baseline. `req-day-log-persists` added. Its proposal's "no new dependency" and "persisting is a
non-goal" lines were false by the end of the change and now say what happened, in order: seam,
decision, implementation.

A ledger box that said "Tier 2 not run" sat twenty-three lines above the proof that it had.
A test named *"renders with its glyph"* checked no glyph. `CLAUDE.md` stated two pure-root counts the
gate contradicts. A PROC-8 citation belonged to PROC-10.

## Still open

- **A zero streak** shown as `0` on a fresh install — §2.
- **`PrefsDayLogStore.record` is a read-modify-write** with no atomicity. Not reachable today: no two
